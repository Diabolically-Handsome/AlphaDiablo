## 〇、施工记录:首轮探针"买了 32 张卷、施法 60 次、一门未开"

首轮探针有效但门一次没开。逐层追查,三个根因、两处接缝,全部在 Python 侧修复,引擎与桥未动:
1. `wait` 指令在引擎里等于"取消当前动作"(player.Stop,施法动画中直接站定),脚本用 wait 等门,把刚排上的施法掐掉 → 新增 `hold` 指令(只推进引擎,不取消);
2. 每个动作之后的通用收尾栅栏同样取消意图 → 被接受的施法先推进到门出现或动画回到站立(上限 16 拍),与开门(open)同法;
3. 被近身怪打中会打断读卷 → 施法只在 2 格内无怪时进行,有怪就沿撤退路线往上楼梯走,60 拍内没等到空档就交还(走楼梯撤退接手);
4. 回城服务在城里从不交还控制,女巫买卷无处安放 → 买卷嵌进回城行程的"返回"阶段之前(先判断再下令,不留悬空回执),并记入卖装备账本;
5. 从门到城后,原有回城流程(治疗、买药、卖装备)接不上,脚本 6 拍就回门 → 门到城即从"outbound"阶段进入原流程(跳过只属于 L1 的拾金阶段),
   流程走到返回阶段时关闭回城服务并交给门的返回腿(先判断再下令)。
修后冒烟(种子 2133010):两个完整循环——买卷 → 血 36 开门 → 城里治到 86 → 从城里的门落回二层原地 → …… → 第二轮血 35 → 94,活到钟响。
重跑探针的对照臂行与 R18-G 对照臂逐位相同(剔除探针后来新增的两个 None 键;驱动首次误判 VOID,已更正入账)。**探针有效(REPORT_ONLY)。**

## 三、解读

也没有明显推进(L3 4 vs 2 在噪声范围)。原因和 R18-C 一样:回到二层面对的还是同一群怪、同一个打不赢的工人;
