# 从1级开局到击杀屠夫：首次可复现胜利

2026-09-13 · [English / 完整方法与证据](README.md) · [录像下载](https://github.com/Diabolically-Handsome/AlphaDiablo/releases/tag/butcher-first-kill-20260913)

![原生引擎重放画面](media/poster.png)

**这次真的打赢了。** 角色从1级开始，在游戏里练级、捡装备、购买补给，
到6级时击杀屠夫，结束时剩 **83/110生命、1份治疗用品**。没有预装后期
神装，也没有在效果局里额外发经验、装备或药品。同一开局原封重跑也成功。

这不是“1级打赢屠夫”，而是“从1级发育起来，最后打赢屠夫”。

## 这次突破来自哪里

主要修正的是装备评分：以前在扣除敌人护甲之前，就把命中率封顶了，
使一些实际有用的命中加成看起来毫无价值。新规则先减去固定参考护甲，
再应用游戏里的命中上下限。修改的是装备评分，不修改实际战斗公式，
也没有给人物增加属性。

固定参考护甲50来自普通难度屠夫的公开数据，是任务先验，不是偷读未见
怪物。它还不是适用于所有敌人或16层通关的最终评分。

新路线见到屠夫时有23护甲、完好的胸甲、盾和7份治疗用品；旧路线是
19护甲、磨损严重的胸甲和4份治疗用品。但两条路线此时的原始命中相同，
所以不能把胜因简单说成“最后那把武器命中更高”。装备、补给和路线的
各自贡献尚未完全拆开验证。评分也会进入模型观测和奖励，不能把这次
实验说成“除了最后换一把武器，其余过程完全相同”。

## 不夸大的地方

- 这是混合系统：模仿学习训练的战斗工人、RL来源的探索模块，以及脚本
  补给、撤退、换装和动作宏。此次装备修正没有新增模型训练。
- 模型读取结构化引擎状态，不是像人一样看画面、操作鼠标键盘。
- 旧装备宏本来就包含不另收费的自动鉴定；这项规则两组一致，但与完整
  原版鉴定流程不同。正常低等级开局不等于全程所有规则都和人类相同。
- 新方案在两个已用开发开局中 **1胜1负**。同一开局重复成功，只能说明
  可以复现，不能当成独立胜率样本。目前还不能说“稳定击杀”。
- 不宣称全球第一、纯RL完成全流程、毫无辅助，或已经连续通关16层。

## 录像和证据

原始实验没有画面。此次录像来自同一获胜开局的独立录制重放：把实时状态
复制到一次性子进程，调用原生引擎绘制，子进程不推进游戏。主进程继续
原来的无画面运行。只有结果、屠夫任务状态及9份装备/补给/战斗记录与
原始胜局完全一致，录像才可发布。

录像前段是标注过的发育节点快照；屠夫战斗段按桥接步连续展示，附加信息
面板，无游戏音频。没有用动画猜测战况或补造击杀画面。

真正的击杀依据是原生屠夫任务从未完成变为DONE，并且人物仍然活着；
不是拿低血量、得分或Python奖励冒充击杀。

这次发布的是成果、精选证据、评分实现差异和录像，不是现役模型替换，
也不是完整的一键复现运行包。冻结模型和环境仍在本地，公开SHA用于辨认；
不上传MPQ游戏资源、存档或模型权重。全部数字、失败结果和证据检查脚本
见[英文主报告](README.md)。
